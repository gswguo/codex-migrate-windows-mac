# 可行性审查与发布条件

设计审查日期：2026-10-27；alpha 状态更新：2026-10-28。

结论：可以发布清楚标注限制的源码 alpha，不能把固定配置的合成验证描述成所有 Windows/macOS 桌面版本稳定可用。当前可重复公开的证据仅使用人工构造的数据，见[验证记录](validation.md)。本页不引用私人迁移案例统计。

## 当前实现

已有选择性导出、显式路径映射、原生事件/展示投影的链接转换、最终字节偏移重建、隔离数据库合并、文件摘要比较发布、恢复日志与中英文入口。

精确匹配 `native-state5-history1-61-8-alpha`；原生 CLI `0.164.0-alpha.11.1` 已在 macOS 合成新建、选择性项目导入及未归属项目聊天导入目标上完成读取/分页/resume 验证。没有发送模型任务。Windows 桌面完整闭环仍未验证。

完整目标数据库先在私人暂存区快照、合并和校验，然后在停机窗口按原文件摘要逐文件发布；不是在线附加库事务，也不是跨文件整体原子提交。发生中断后先恢复，不能先重新打开 Codex。

## 稳定发布仍需补充的证据

| 风险 | 当前边界 | 需要的证据 |
| --- | --- | --- |
| 同 schema 但原生事件、渲染或侧栏语义不同 | 固定 profile，未知格式停止 | 每个声明支持的桌面构建组合验收 |
| Windows 文件占用、刷新与恢复差异 | 有独立平台实现与合成测试 | Windows 桌面正常流程、故障恢复与重启闭环 |
| 文件存在但历史链接点击失败 | 区分存在、摘要和原生点击 | 两个迁移方向的实际文件点击 |
| 同一聊天在两台设备上发生分叉 | 同 ID 冲突拒绝，不按修改时间合并 | 另行设计并验证共同基线交接 |
| 恢复覆盖后来工作 | 所有目标须匹配已记录前/后状态 | 后续聊天、文件编辑、目录占用的保留验证 |
| 历史修复范围扩得过大 | 转换显式选择和后继，祖先只读上下文 | 保持上下文祖先原字节及无关兄弟不变 |
| 私人数据误入公开仓库 | 独立源码、合成 fixture 与提交扫描 | 发布前逐文件及历史审查 |
| 大包超过规划资源 | 256 MiB/数据库结构化规划上限与 ZIP 限额 | 超限拒绝与磁盘不足恢复；不宣称无限数据支持 |

## 不作出的承诺

工具不能在自己崩溃后阻止 Codex 启动。必须由用户维持停机窗口；中断期间若启动了应用，应退出、保全当前对象并检查差异，不能用旧备份直接覆盖后来内容。

不承诺任意 SQLite 布局、网络盘、同步占位文件、Git worktree、符号链接、Markdown 或工具输出都会被支持。不迁移 `.git` 历史、登录凭据、完整配置、插件或自动化；项目和聊天仍可能含秘密。

源码启动器需要现有 Python 3.11+，不会自动安装。当前不宣称有包含 Python 的独立安装包或已签名可执行发行包。合成测试、原生 RPC、桌面可见性和真实文件点击必须分开报告。

准确的命令、容量、停机及恢复说明见[使用指南](usage.md)，发布边界见[源码发布说明](github-publishing.md)。
