# 历史聊天中的本地文件链接修复

状态：alpha 已实现固定原生配置下的 `repair-links` 规划、事件/投影转换、偏移重建与离线发布。本文保留设计要求及人工验收条件；不表示所有语法、Codex 版本或 Windows 桌面已验收。实际命令见[使用指南](usage.md)。

## 1. 解决的问题

项目文件已经完整迁到新设备，但历史聊天中的链接仍指向旧电脑，例如 Windows 的 E: 盘。因此“文件未损坏”“文件已复制”和“历史聊天中可点击打开”是三件不同的事。

本方案必须覆盖原生 Codex 历史聊天的文件引用；生成一个可以打开的 HTML 阅读副本只能作为辅助，不能代替原生聊天窗口修复。

下面的示例路径均为虚构：

```text
旧根：E:/Research/ProjectA
新根：/Users/example/Documents/ProjectA

旧引用：E:/Research/ProjectA/reports/result.pdf
新目标：/Users/example/Documents/ProjectA/reports/result.pdf
```

最终输出的链接编码、空格包裹和行号格式由目标 Codex 版本适配器决定，并必须在原生窗口中验证。不能因为一种 Markdown 语法在浏览器中有效，就假设桌面应用也支持。

## 2. 四层记录

| 层 | 内容 | 是否可改 |
| --- | --- | --- |
| 原始来源 | 私人迁移包中的原始事件与聊天 | 不改，作为证据与重新转换来源 |
| 修复计划 | 旧链接、目标、确认依据、精确补丁、未解决项 | 用户预览后冻结 |
| 工作副本 | 用于新设备原生显示的消息/事件与缓存 | 只按补丁白名单修改 |
| 修复收据 | 前后摘要、对象位置、执行与验证结果 | 追加保存，供恢复和未来交接使用 |

“保留历史”应解释为保留原始副本及语义内容，而不是同时承诺工作副本的所有字节不变。对链接目标进行修复本来就会改变消息字符串和 JSONL 字节长度，必须记录这项有意修改。

## 3. 查找与映射规则

1. 先从迁移清单和用户显式指定的旧根/新根建立映射，不从聊天正文推断需要读取整台电脑的哪些目录。
2. 按来源平台解析盘符、斜杠、UNC、`file:` URL、百分号编码及相对路径。保留路径段边界，使用最长有效根匹配；`E:/a` 不能误匹配 `E:/abc`。
3. 用原聊天所属根或附件清单解析相对链接。多根项目中若存在多个合法候选则标记歧义，不挑第一个。
4. 确认目标位于用户选择的目录内，规范化后无越界或符号链接逃逸。
5. 对包内文件使用清单摘要校验。对于迁移后用户重新定位的外部目录，用旧文件摘要清单核对；若缺旧摘要，只能证明目标存在，状态写“用户指定，无法证明与原文件一致”，不能宣称已核对相同。
6. 同名文件不会自动配对。目录链接检查目录映射和清单范围，不把目录当作普通文件做单文件哈希。

只读扫描分为以下状态：`verified`、`user-mapped-unverified`、`missing`、`ambiguous`、`unsupported-syntax`、`external-url`、`plain-text-reference`。报告显示数量和可操作原因。

## 4. 精确修改范围

| 引用形式 | 处理策略 |
| --- | --- |
| Markdown 链接 `[报告](E:/.../报告.pdf)` | 精确改链接目标，保留标签和相邻文字 |
| Markdown 图片和可支持的引用式链接定义 | 由语法解析器定位，目标通过核验后修改 |
| 原生结构化附件/图片字段 | 按版本适配器的字段路径改写 |
| 可明确识别的系统文件引用块 | 在已验证字段范围内转换；语法不明则报告 |
| 代码块、命令示例、普通叙述中的 `E:` | 默认保留，不做全局字符串替换 |
| HTTP(S) 或其他外部 URL | 保留，不抓取网页来验证本地迁移 |
| 解析不支持或目标存在歧义 | 报告待处理，禁止猜测 |

解析器必须能可靠定位原文中的目标范围，并证明修改未影响代码块和可见叙述文字。括号、空格、中文、反斜杠转义、行号/锚点、百分号编码、引用式定义、重复出现相同 URL 都必须有测试。没有可靠位置或格式支持时保留原文并报告，不降级为全文 `replace()`。

显示为纯文字的路径可在只读修复报告中提供一个新的可点击链接；首版不默默将普通文字改造成 Markdown。若后续增加此模式，需单独显示变更预览和验收。

## 5. 原生聊天写入与一致性

不能只改 `thread_items.item_json` 或只改 rollout。版本适配器需要枚举同一内容出现的权威事件字段、展示投影和缓存，形成一个对象级补丁集合。未知重复表达形式拒绝原生补丁。

流程为：

```mermaid
flowchart LR
    A[引用扫描] --> B[路径映射与文件校验]
    B --> C[精确链接补丁]
    C --> D[事件及展示投影同步转换]
    D --> E[祖先依赖排序与字节偏移重建]
    E --> F[全文分页和允许差异核验]
    F --> G[离线备份与提交]
    G --> H[重启后实际点击验证]
```

链接字符串变长或变短都会影响后续字节偏移。必须重新计算 turn 的起止 offset、projection 的 next offset、历史继承 `history_base` 的字节边界；保留 ordinal 和聊天/turn/item ID。

原地修复仅转换显式选择及依赖这些聊天字节边界的现存后继；所需祖先作为只读上下文，其事件字节保持不变，不因共用祖先而把无关兄弟加入转换范围。若原地修复发生在父聊天中，所有依赖其历史边界的后继文件也可能需要更新，即使用户只选择了父聊天。计划阶段必须在完整目标依赖图中计算并显示这部分反向依赖闭包；缺少必需对象或用户拒绝扩大范围时，取消该批原生修复。

首次导出到新目标是另一种情况：来源保持不变，只处理所选聊天及其必需引用；仅因另一个未选聊天也继承同一祖先，不要求把它一并导出。例如选中 A 且 A 继承 P，未选 B 也继承 P，导出 A/P 并不自动包含 B。两种范围规则须独立测试。

## 6. 已迁入聊天的独立修复模式

`repair-links` 已是可执行命令，但只生成计划，需要显式旧新根映射和至少一个 `--thread-id`；检查后另用 `apply --yes`。当前 alpha 复用预检、完整目标数据库暂存快照、摘要比较发布及恢复日志：

1. 用户选择聊天范围和已经找到的新目录。
2. 读取现有目标快照，生成修复清单和一致性证据。
3. 不重复复制已经存在且一致的项目目录。
4. 在隔离副本修改链接、相关事件和索引；验证展示内容只存在允许的差异。
5. 用户退出 Codex 后重新核对目标指纹，备份所有即将修改的对象。
6. 在隔离历史数据库副本内替换所选范围的数据行，并发布整份已校验数据库及改变的事件文件；不在线 UPDATE 正在使用的数据库。目标文件需仍匹配原摘要，发布逐项记日志。首次导入也在完整目标快照中合并允许的新增行，再比较并发布。
7. 用户重启后检查链接；记录文件存在、摘要一致、原生点击通过三个独立结果。

如果预览之后用户续聊，或目标被同步程序/其他进程改动，旧计划失效，必须重新生成。回滚时也不覆盖修复后用户新增的聊天或修改。

修复从开始写入到验证完成是停机窗口。若程序中断，用户须先运行恢复入口，再启动 Codex。首版无法在工具已经崩溃时拦截系统启动 Codex；若中断后已打开 Codex，先退出、保全当前所有相关对象并检查差异，不自动覆盖恢复。这个前提必须出现在使用说明和错误提示中。

## 7. 首版验收用例

| 用例 | 必须结果 |
| --- | --- |
| Windows E: → Mac，PDF/DOCX/XLSX/图片 | 所选文件摘要一致，链接格式符合目标应用，实际点击打开 |
| Mac → Windows，包含中文与空格 | 链接指向目标盘符文件，实际点击打开 |
| 同名不同内容文件 | 不自动绑定，报告歧义/摘要不一致 |
| 缺失或未打包文件 | 报告缺失，不创建空壳文件伪装恢复 |
| Markdown 嵌套括号、引用式链接与行号 | 精确改目标，可见文字及行号语义正确 |
| 代码块中含旧 E: 路径 | 原样保留 |
| 同一聊天投影与事件含相同链接 | 两处一致，后续重新投影不会复活旧路径 |
| 修复祖先聊天导致文件变长 | 子孙继承边界仍正确，全部分页无缺漏 |
| 修复中断或重启时被用户续聊 | 可恢复或明确停止，不覆盖后续新增内容 |

检查结果必须允许“聊天恢复成功、部分外部文件未纳入”的分项状态。只有所有声明为自动修复的链接都经过对应验证，才能显示“链接修复成功”；不能把 unresolved 项藏在日志中。

当前合成原生验收与未完成边界见[验证记录](validation.md)。
